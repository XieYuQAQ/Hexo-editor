# Hexo 文章编辑器

纯前端（无后端、无构建、无依赖安装）的 Markdown 文章编辑器，直接读写本项目的
`source/_posts`，格式与站内已有文章完全一致。

```
hexo-editor/
├── index.html              界面（双击即用，不需要任何服务）
├── assets/
│   ├── core.js             格式层：Front Matter 解析/序列化、abbrlink(crc32)、文件名、视频块
│   ├── app.js              编辑器主程序
│   └── editor.css          样式
└── test/                   7 套自动化测试（473 条断言）
```

---

## 一、怎么打开

**双击 `index.html`**，用 Chrome / Edge 打开（Firefox / Safari 没有 File System
Access API，只能「导入文件夹」只读编辑 + 下载，见下方说明）。

**只有第一次打开、或有目录没连上时才会弹出「连接目录」引导**（里面分别连
`文章目录`（必填）和 `图片目录`（可选），连完点「进入编辑器」）。两个目录都连好之后，
以后再打开就直接进编辑器，不弹任何窗口。目录记在浏览器里，下次打开自动恢复；
连没连上，看左下角列表底部的两个圆点（绿=已连接，红=未连接），点圆点随时能回来换目录。

> 选项目根目录最省事（编辑器会自动找到 `source/_posts` 与 `source/images`）；
> 选 `source` 或直接选 `_posts` 也都能识别。

**关于 `file://`**：`file://` 的 origin 虽然是 `null`，但 Chromium 只在「跨源子框架」
「没有用户手势」时拦目录选择器，不拦 `file://` —— 双击打开同样能直接写盘
（2026-10 实测）。唯一代价是源不透明，浏览器对目录授权的长期记忆不可靠：重开浏览器后
圆点可能变红并提示「已记住 X，需要重新授权」，点一下「重新授权」即可，不用重新翻目录。

> 早期版本这里写着「`file://` 下 API 被禁用、只能导入并下载」，那是把 OPFS 的规则
> 错套到了 picker 上 —— 已实测推翻。

不再需要本地服务：原来的 `serve.mjs` / `start-editor.bat` 已删除，纯静态文件即可运行。

## 二、能做什么

### 文章属性（对应 Front Matter）

| 面板上的名字 | 字段 | 说明 |
|---|---|---|
| 标题 | `title` | 必填 |
| 链接 | `abbrlink` | **新建时锁定**；`hexo generate` 写入文件后，点 ↻ 重新读取即解锁 |
| 文章描述 | `description` | 单行自动转标量；多行自动变成 `>-` 折叠块（与站内 5 篇文章一致） |
| 标签 | `tags` | 内联数组 `tags: [网站, 软件]`；带站点已有标签的联想 |
| 时间 | `date` | **新建后锁定**；文件保存一次后解锁，格式 `YYYY-MM-DD HH:mm:ss` |
| 封面 | `cover` | 站内绝对路径 `/images/...` 或完整 URL；可从本地选图并自动复制进 `source/images/YYYY/MM/` |

锁定逻辑按你的要求实现：

- **abbrlink**：读到文件里已有值就解锁；为空时锁定，并提示「generate 后自动填入」。
  点锁图标可临时手动解锁；「预估 abbrlink」按钮会按 `_config.yml` 的
  `abbrlink.alg: crc32` + `rep: hex` 算出 `crc32(title)` 供参考
  （注意 Hexo 只在缺失时写一次，改标题不会重算，所以只是预估）。
- **date**：新建 → 锁定（创建时定好）；保存后 → 解锁。

### 正文（所见即所得）

正文区**不再是纯文本框**，也不再需要手动开预览：打字时块级效果立刻生效 ——
输入 `#` + 空格 + 文字，这一行马上变成一级标题（H2 到 H6 同理），
`> ` 变成带竖线的引用、`- ` 变成 • 列表、` ``` ` 变成代码块底色。

- **光标所在的那一行显示原始 markdown**（`#`、`**` 都在），方便改标记；
  光标一离开，这一行就渲染成最终样子：标题变大、标记隐藏、`**粗体**` 真的加粗。
- 回车自动延续列表（`- `、`1. `、`> `、`- [ ] `），在空的列表项上回车会退出列表；
  行首退格会把两行合并。
- **保存的永远是原始 markdown**：渲染只是视觉层，标记以隐藏 span 的形式留在 DOM 里，
  所以 90 篇文章「文本 → 编辑区 → 文本」逐字节一致（`test/wysiwyg.test.mjs`）。
- 撤销/重做是自己实现的栈（工具栏 ↶ ↷ 和 `Ctrl+Z` / `Ctrl+Shift+Z`），
  不依赖浏览器的原生撤销；中文输入法组字期间不做任何 DOM 手术，不会打断候选词。
- **表格直接长成表**：连续的 `| a | b |` 行拼成一张真表（表头加粗底色、
  `:---:` 对齐生效、分隔行收成一条细线，悬停可展开去改）；点进任意一行
  该行回到原始 `| a | b |` 供编辑，光标一走立刻恢复表样。
- **图片直接显示**：行内图片显示为小缩略图，**整行只有一张图时显示为最大
  300px 的大图**；图挂了（路径失效/没连图片目录）自动退回「🖼 alt」小徽标。
  图片按缓存读取（IndexedDB 里存 blob URL），不重复读盘。

工具栏覆盖：H1–H6、加粗、斜体、删除线、行内代码、文字颜色（`<font color>`）、
无序/有序/任务列表、引用、链接、图片、表格、代码块（可填语言）、分割线、
`<!-- more -->`、`<kbd>`、上标、下标、折叠块、居中容器、脚注、撤销/重做。

**插入图片**：点「图片」选本地文件，或直接把图片拖进编辑区 ——
图片按年月存进 `source/images/YYYY/MM/`，**文件名自动换成 10 位随机字母数字**
（如 `7k3f9a2c1d.png`，后缀沿用原文件），正文插入 `![](/images/YYYY/MM/7k3f9a2c1d.png)`。
「封面」里的「选图」走同一条路径，命名规则一致。

**插入视频**：点「▶ 视频块」，填哔哩哔哩 BV 号 / YouTube 链接。默认勾选
**「判断网络，自动选择哔哩哔哩 / YouTube」**（两个平台都必须填），生成的代码
与站内 23 篇文章完全相同：

```html
<div id="videoContainer">
  <p>请稍等，正在根据您的网络加载播放器……</p>
</div>
<script>
  function loadBilibiliVideo() { ... }
  function loadYouTubeVideo() { ... }
  checkGoogle().then(function(status) {
  if (status === 0) { ...哔哩哔哩... } else { ...YouTube... }
  });
</script>
```

**取消勾选**则只需填其中一个平台，生成单平台 iframe（不判断网络、不带 script）。
支持两种布局（等比 16:9 / 固定高 450），并可追加 `> 视频 / > 哔哩哔哩 ... / > YouTuBe ...` 引用块。

**视频块在编辑器里可直接预览**：折叠态显示成 16:9 的播放器 iframe（哔哩哔哩优先），
块内源码隐藏；点进块内任意一行即展开全部源码供编辑，光标移出后自动折叠回播放器。
代码块（```）里的视频块示例代码不会被误识别。

### 其他

- 引导只在「第一次打开」或「有目录没连上」时弹；两个都连好后打开不再有任何弹窗
- 目录记在浏览器里（IndexedDB 存 handle），下次打开自动恢复；授权过期时点「重新授权」
- 连上目录后右侧编辑区是**灰色不可用**的空态，点左侧文章或「＋ 新建」才有内容
- 打开文章后左侧列表自动收起，顶部 ☰ 按钮点一下弹回来；没打开文章时列表始终展开
- 列表底部一行：`x / y 篇` + 两个圆点 **绿=已连接 / 红=未连接**，点一下能重开引导换目录
- 保存状态（未保存 / 已保存）在属性面板底部、「预估 abbrlink」右侧
- 头部从左到右：☰ 列表开关 → 主题三段按钮（☀ 白天 / ☾ 黑夜 / ◐ 跟随系统）→ **居中的文件名**；主题选择存在 localStorage，下次打开不闪
- 白天 / 黑夜两套配色由 CSS 变量切换（`html[data-theme="light"|"dark"]`），跟随系统时监听 `prefers-color-scheme` 实时切换
- 左栏搜索（标题 / 文件名 / 标签）、标签点选筛选、「未保存」过滤、三种排序
- `Ctrl+S` 保存、`Ctrl+B/I/K`、`Ctrl+2/3/4`、`Shift+Ctrl+N` 新建
- 未保存内容自动存 localStorage 草稿，下次打开会询问是否恢复
- 改文件名保存时，会询问是否删除旧文件（避免出现两篇重复文章）
- 「复制」以当前内容生成新文章，「删除」二次确认

## 三、格式兼容性是怎么保证的

`assets/core.js` 只做**最小必要解析**，核心策略是：**没改过的字段按原始行逐字节回写**。

因此：

- 对全部文章执行「读入 → 直接序列化」，结果与磁盘文件**逐字节相同**
  （`test/roundtrip.test.mjs`：当前 90/90，含临时测试文章）
- 字段顺序、空 `cover:` 的写法、`description: >-` 折叠块、单引号包裹、
  行尾有无空白、结尾有无换行，全部原样保留
- 只改一个字段时，差异只落在该字段那一行（`test/edit.test.mjs`）

新文章则按站内主流顺序生成：
`title → abbrlink → description → tags → date → cover`，
`abbrlink` 留空、`cover` 留空（都输出成 `cover: `，与 45 篇无封面文章一致）。

文件名建议规则复刻现有命名：`<两位年份> <标题>.md`（如 `26 迈从G3 A鼠标开箱.md`），
也可切换成 `YYMM` 或纯标题。

### 端到端验证

已用编辑器生成一篇包含标题/列表/表格/代码/图片/字体颜色/视频块的文章，
放入 `source/_posts` 跑 `hexo clean && hexo generate`：

- `abbrlink` 被自动填入（`37fab123`），生成 `public/37fab123.html`
- HTML 里 `<h2>`、`<table>`、`<img>`、`<font color="red">`、
  视频 `<script>` 与 `checkGoogle()` 全部原样输出

## 五、已知边界

- **只支持 Chromium 系浏览器**（Chrome / Edge）直接写盘；Firefox / Safari
  连这三个 picker 都没有，只能走导入降级模式。这是浏览器 API 的限制，不是实现问题。
- 纯静态、无服务：全部功能都在 `index.html` + `assets/` 里，双击即用；
  没有构建步骤，也不需要 `node`。
- `file://` 可以直接写盘，但源是 opaque —— 目录授权存进 IndexedDB 后，
  重启浏览器能否免授权不一定，多半要重新点一次「重新授权」（不用重新翻目录）。
- `abbrlink` 预估只是参考值：Hexo 采用「有就不改」的策略，
  且冲突时会 +1 避让，最终以 `hexo generate` 写入的为准。
